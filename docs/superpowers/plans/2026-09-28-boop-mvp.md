# Boop MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use an execution workflow task-by-task. Every task ends with its own tests and a reviewable commit; do not skip forward when a gate fails.

**Goal:** Build a production-capable, low-resource personal blog that matches the approved Boop V7 visual and supports owner publishing, reader interaction, configurable moderation and AI features.

**Architecture:** A single Go process serves SSR HTML, embedded assets and JSON APIs. SQLite is the only stateful service. Code is organized as small vertical modules with shared HTTP and database infrastructure; no SPA, Redis, queue or speculative abstraction.

**Tech Stack:** Go 1.27, `net/http`, `html/template`, `modernc.org/sqlite`, `goldmark`, `bluemonday`, `golang.org/x/crypto`, vanilla CSS/JS.

## Global Constraints

- Project root is `D:/工作文件夹/Boop`.
- All downloaded Go modules and build cache go to `G:/Go/pkg/mod` and `G:/Go/cache`.
- Preserve the approved visual source at `D:/工作文件夹/.superpowers/brainstorm/visual-1790566406/content/boop-x-native-v7.html` as read-only reference.
- Only the owner publishes; readers never receive content-write permissions.
- External behavior follows `docs/PRODUCT.md`, `docs/DATABASE.md`, and `docs/API.md`.
- No Node toolchain, ORM, Redis, Docker requirement, code generator, repository pattern or interface with one implementation.
- Every write route has authentication, authorization, CSRF, body limits and deterministic validation errors.

## Plan self-review

- Product requirements map to Tasks 1–10; v0.2 semantic/vector enhancement is deliberately gated behind measured need.
- Every write path is covered by auth, role, CSRF, validation and tests.
- No task requires Node, Redis, a separate worker or a second process.
- The first independently runnable checkpoint is Tasks 1–2; the first user-complete publishing checkpoint is Tasks 1–5.
