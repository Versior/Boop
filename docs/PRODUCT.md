# Boop 产品方案 v0.1

## 1. 产品定位

Boop 是面向个人站长的轻量自托管博客：公开页面保留 X/Twitter 式信息流节奏，发布体验借鉴 Ech0 的快速输入，但不复制社交平台关系链。系统只允许站长发布，读者可注册后评论、回复、点赞和收藏。

## 2. 成功标准

- 1 核 512MB 可稳定运行单实例，推荐 1GB。
- 单个 Go 二进制 + SQLite + 本地上传目录即可部署，无 Node 运行时、Redis、消息队列；上传目录可以换成兼容 S3 的对象存储（见 `docs/STORAGE.md`），换了也不会改变这条：仍然是同一个二进制、同一个 SQLite、同一个进程。
- 首页首屏 SSR；关闭 JavaScript 后仍能阅读文章、摄影和动态。
- 空闲 RSS 目标小于 100MB；缓存命中时首页服务端响应目标 p95 小于 100ms。
- 管理员能在首页直接发布动态、文章或摄影，无需进入复杂后台。

## 3. 角色与权限

| 能力 | 游客 | 注册读者 | 站长 |
|---|---:|---:|---:|
| 阅读、查看 AI 作者状态 | 是 | 是 | 是 |
| 评论与回复 | 否 | 是 | 是 |
| 点赞 | 否 | 是 | 是 |
| 收藏与查看个人收藏 | 否 | 是 | 是 |
| 发布、编辑、删除内容 | 否 | 否 | 是 |
| 评论审核、系统设置、AI 设置 | 否 | 否 | 是 |

第一位通过初始化命令创建的账户为站长；公开注册永远只能创建 `reader`。

## 4. 内容模型

- `moment`：短动态，正文必填，最多 2,000 字，可附图片或链接。
- `article`：长文章，标题必填，Markdown 正文必填，可配置摘要、封面、标签和 SEO 字段。
- `photo`：摄影内容，正文可选，至少一张图片，可保存地点和拍摄时间。
- 内容状态：`draft`、`published`、`archived`。只有 `published` 出现在公开页面。
- 删除采用软删除；资源文件仅在确认无引用后由维护命令清理。

## 5. 核心体验

### 5.1 首页

- 中栏顶部是作者头部：封面图（**有出厂值**，随发行版一起发布的那张横幅；清空这一栏才不画）、单占一行并压住封面下沿的大头像、名称与站长标识同行、一句站点简介，以及带图标的一行事实——RSS 订阅、始于、最近更新于（后两者取自信息流自己列出的内容，即最早一篇与最近一篇的发布时间）。它是站点自己的门面而不是用户主页——Boop 只有一个作者、没有关注关系，所以不放关注/粉丝这类这里根本不存在的计数；也**没有统计数字那一行**（站长给的那张个人主页截图里那一行是「关注中 / 关注者 / 获赞」，他明确说不要，改为把简介放在那里）。
- 作者头部下面是内容类型行：全部、文章、摄影，每一项带已发布内容的条数。它只列服务端真正接受的筛选值，动态没有自己的入口，因为动态只在“全部”出现。
- 作者头部只画在信息流第一页，带 `cursor` 的续页不重复它（类型行照画）。
- X 风格三栏桌面布局；中栏为信息流，右栏为 AI 作者状态。
- 左栏是图标栏：最上面是品牌（出厂名 `Boop` 下画那枚字标，站长改了站名就退回「方块标记 + 站点名」），中间是四个目的地（首页、文章、摄影、收藏），最下面是控件组（外观开关；站长登录时另有「站长后台」与「退出登录」，未登录时为「登录」）。**导航不带文字**：每一项的文字留在无障碍树里并另带 `title` 提示，只有品牌是可见的——「这是哪个站」不是图标能表达的事。
- 品牌有两副面孔，由 `pageView.SiteWordmark`（站名是否仍等于 `settings.Defaults().SiteName`）挑一副，三处复用（前台左栏、移动端顶栏、后台侧栏）。**出厂名下画字标**：内联的 `#i-wordmark`，viewBox 已收到字形本身（2.65:1），`fill:var(--ink)` 所以深浅主题各取自己那一档，只定宽——左栏 120px、移动端顶栏 92px、后台侧栏 108px（左栏那 120px 有个算出来的上限：180 − 左右各 14 的栏内边距 − `.brand` 自己的左右各 8 = 136px，再宽就把左栏顶歪）。**站长改了站名就退回排版**：字标拼的是「Boop」这一个词，只能替这一个词，留着一枚不属于自己的名字比换回文字更糟；退回时前面补一块 34px 方块标记（字标自己不配，它已经是一整套字形），文字用系统自带的高对比衬线（Didot / Bodoni 72 / Georgia / Songti SC / SimSun 等，不下载任何字体文件），23px / 700——高对比衬线的细笔画在 19px 上不足一个像素、被屏幕抹成发虚的灰字，23px 才让它落回 1px 以上，同时粗笔画约 2.5px，与那块标记里的单线（描边 1.8/24）实际粗细一致；末尾另有一颗蓝色圆点（CSS 伪元素，接在文字之后），与标记里那颗蓝点是同一颗，站长改了站名这点也还在。字标那条把站名照留一份在无障碍树里（`.sr-only`）：那枚 svg 是 `aria-hidden` 的，不留真文字，这个链接就没有名字了。退回排版那条有一个这一栏宽度带来的代价：180px 的左栏扣掉边距只剩 135px，放不下「34px 标记 + 一个长站名」，超出的部分以省略号收尾（`text-overflow`）——五个汉字就已经开始收；这是图标栏换来的，不是字号的问题（把字号调小只会回到笔画发虚那一步）。
- 站长登录时，左栏底部控件组里有后台齿轮（`/admin` 入口），指向管理页；游客与普通读者的 DOM 里没有这个入口。
- 移动端为单栏，AI 作者状态在作者头部与类型行之后、快捷发布之前（那两块是这一页的坐标，卡片是旁边的附注，插在两者中间会把头部和它自己的类型行拆开），底部导航为首页、文章、摄影、收藏、登录。
- 站长登录时显示快捷发布器；游客和普通读者不渲染发布器 DOM。
- 首页可按全部、文章、摄影筛选；动态只在“全部”出现。

### 5.2 认证

- 邮箱 + 密码注册登录；邮箱无需验证。
- GitHub OAuth 登录；若邮箱与已有账户匹配，只有在 GitHub 返回已验证邮箱时才允许绑定。
- 管理后台可关闭公开注册；关闭后仍可登录和使用 GitHub 绑定的现有账户。
- Session 使用 HttpOnly、SameSite=Lax Cookie；生产环境必须 Secure。

### 5.3 互动

- 评论支持一级回复，最大深度 2。
- 评论审核开关开启时，新评论为 `pending`，否则为 `approved`。
- 点赞和收藏均为登录用户幂等切换；同一用户同一内容最多一条记录。
- 站长可批准、拒绝或删除评论。

### 5.4 AI

- OpenAI-compatible 配置：Base URL、模型、API Key（对话与嵌入模型各一个字段，嵌入用于 v0.2）；密钥使用 `BOOP_MASTER_KEY` 经 AES-GCM 加密后入库。每条密文以它自己的 settings key 作为 additional data 绑定，因此密文只能解回原 setting，换 key 或换行都会认证失败。设置与密钥在每次调用时重新读取并解密，改动无需重启。
- 作者状态：显示在首页右栏顶部；右栏隐藏的窄屏改为显示在快捷发布器之前。内容是不超过 280 字的纯文本加最多 5 个主题词。访问首页时读缓存：仍新鲜直接返回；缓存过期但最新已发布内容的 `updated_at` 不晚于 `source_updated_at`（内容没变，或删除、归档让这个最大值回退；时间戳无法解析时按“可能更新”保守处理）时继续用旧值且不调用模型；缓存过期且存在**严格更新**的内容时先返回旧值，再单飞后台刷新（并发访问不重复生成，失败保留旧值并只记录短码；首次生成失败写入一行只有短码与 5 分钟退避的最小占位行，保持手写兑底文案且退避期内不再打上游）；完全没有缓存时返回手写兑底文案。刷新永不阻塞首页渲染；站长可手动刷新，已有刷新在跑时提示“忙碌”。
- 文章助手：只在站长 + 文章模式的快捷发布器内，以行内控件提供摘要、标签与 SEO 建议（该控件只在 `ai.api_key` 能真正解密且非空时渲染，缺少 `BOOP_MASTER_KEY` 或密文损坏时隐藏，不提供必然失败的按钮）；建议不会自动覆盖草稿，摘要与标签必须点“采用”才写入，SEO 只提供复制。输入与输出都有明确上限（摘要 300 字、标签 8 个且每个 30 字、SEO 标题 160 字与描述 300 字）。
- 语义搜索与站内问答属于 v0.2，且只在真正需要时再引入：先想清楚要在什么数据结构上检索，并且只有在配置了 embedding 模型并测量之后才考虑向量表。**当前站内没有任何检索入口**。
- 所有 AI 调用都有超时（20 秒）、并发上限（全进程 2 个）、请求与响应体上限和失败降级；密钥、提示词、模型输出与上游响应体不进入错误信息、日志或缓存。

### 5.5 RSS

- RSS 2.0 输出在 `/feed.xml`：最新 50 条已发布内容，用一条只读 `slug`/`type`/`title`/`body_markdown`/`excerpt`/`published_at` 的窄查询，不读 `body_html`、图片与标签；绝对链接只来自 `BOOP_BASE_URL`（不读请求 Host 或转发头）；描述是**真正的纯文本**（文章正文经 Markdown 渲染后只取可见文本，原始 HTML 不会出现）并由编码器自动 XML 转义；页面 `<head>` 带 `rel="alternate"` 发现链接。
- **站内搜索已移除**，不在 v0.1 范围内。它曾经是一套基于 SQLite FTS5 的关键词检索（`/search` 页面 + `/api/v1/search`），现连同 FTS5 索引表 `post_search` 与它的三个触发器一起删除（见 `docs/DATABASE.md`）。要找回内容，读者用 RSS 或浏览信息流，不通过站内检索。

## 6. 站长后台

### 6.1 导航

- 后台只有站长进得去：游客被送到登录页，普通读者得到 403。
- 后台不沿用前台的导航。前台的四个入口（首页/文章/摄影/收藏）在管理页里没有意义，沿用还会让两套界面长得一模一样。后台渲染自己的一套：桌面是带文字的左栏（品牌、设置、评论审核、回到前台、退出登录），移动端是底部三条（设置、评论、回到前台）；当前模块高亮并带 `aria-current="page"`。两套导航是二选一，同一个页面里不会同时出现。
- 后台是两栏（带文字的侧栏 + 中栏），不渲染首页右栏：作者状态卡片只属于首页。
- 侧栏在 900px 以下收起，同时显示顶栏与底部导航：侧栏和中栏在这个宽度里放不下（前台 180 + 600、后台 230 + 600）。两套界面共用同一道断点。

### 6.2 设置分类

设置按主题拆成五个子页，页面顶部那一排标签是它们之间唯一的通路（当前分类高亮并带 `aria-current="page"`）：

| 分类 | 内容 |
|---|---|
| 站点 | 站点名称、简介、头像、封面图、图标、时区、每页条数 |
| 注册与评论 | 公开注册开关；评论总开关与审核开关 |
| GitHub 登录 | GitHub OAuth Client ID/Secret |
| AI | AI Base URL、模型、加密 API Key、状态缓存天数 |
| 存储 | 上传的存放位置（本地目录 / 对象存储）、桶的 Endpoint/Bucket/读取地址/区域/前缀，以及加密保存的两个凭据 |

- 每页的表单只提交属于自己这一类的字段：后端 `PATCH /api/v1/admin/settings` 的每个字段都是可选的、缺省即保持原值，所以一页不需要把别的页的字段原样回传，也不会互删彼此的设置。
- 每页的标题就是分类名（例如「站点设置」），保存按钮同样带上分类名。**页头只有标题与一句说明**，模块归属不另占一行：标题之上再写一行「站长后台 · 设置」，加上表单里再讲一遍同一个意思，同一屏里就要读三遍同样的话。
- 只有含密钥的三个分类（GitHub 登录、AI、存储）在缺少 `BOOP_MASTER_KEY` 时显示警告；无密钥的分类不显示。
- 站点名称、简介、头像、封面图、图标、时区、每页条数的实际行为：名称与头像会真实用于页面品牌（标题后缀、导航品牌、首页文案）与内容头像，头像留空时依次回退到站长账号头像、内置图标。图标是浏览器标签页图标，与头像分开配置，留空时依次回退到站点头像、内置图标。封面图只画在首页作者头部与索引页的链接预览里（预览优先级：封面图 → 头像 → 图标）；清空这一栏时首页不画那条横带（`.author-head.is-plain`）。
- **封面图有出厂值**：新站点打开就带着随发行版一起发布的横幅（`web/static/brand/boop-cover.png`，1200×400，正好 3:1），而不是一条空白的作者头部。**清空这一栏**才是「不要封面」——`has-cover` 与 `is-plain` 两种形态都保留着，否则站长没有任何办法表达「不想要这张横幅」。出厂值写成站点自己的路径而不是绝对地址，因为默认值在播种时并不知道站点的域名，写死就会把播种那一刻的域名焊进每一个新装。升级已有站点不会改写它已经存下的值（种子只写缺的键），所以老站点维持原样，封面照旧由站长决定。
- 三个图片地址（头像 / 封面图 / 图标）接受两种写法：**不带凭据的 http/https 绝对地址**，或以 `/` 开头的**本站路径**。后者是必要的：上传接口返回的就是 `/uploads/…` 这样的路径，只收绝对地址等于让站长自己把源站拼在前面。仍然拒绝的只有三种——协议相对地址（`//host/…`，看着像本站实为跨域）、反斜杠（浏览器会把它当斜杠，`/\host/…` 会绕过上一条）、以及一切非 http(s) 协议（`data:`、`javascript:`、`blob:`）。
- **存储是这一页唯一会改变资源地址的设置**。保存后立刻生效（不必重启）：进程启动时读一次、每次保存设置后再读一次，其余时间只读内存里的快照。但**切换存放位置不会移动已经存在的对象**——`assets` 表只记键，地址一律按当前配置生成——所以换到对象存储之前必须先把本地目录里的对象按原路径搬进桶里，页面上常驻一条红色警告来交代这件事（见 `docs/STORAGE.md`）。
- `BOOP_R2_*` 环境变量只在站点还没有保存过存储分类时播种一次；保存过一次之后以网页为准，环境变量不再生效。缺少 `BOOP_MASTER_KEY` 时凭据无法加密入库，此时什么都不写、进程继续按环境变量跑——这正是升级前就设好 `BOOP_R2_*` 的部署不会在升级后把新上传写进本地目录的原因。
- 存放位置在网页端**二选一**（本地目录或对象存储），但上传路径本身不能任意填写；**单文件大小上限与允许的 MIME 类型仍然只由环境变量控制**。

## 7. 非目标

- 不做关注、转发、私信、用户发帖、多人协作发布。
- 不引入 Redis、Elasticsearch、独立前端 SPA、任务队列或微服务。
- 不引入 AWS SDK：对象存储只用到 PutObject 与 DeleteObject 两个操作，用标准库手写 SigV4 即可，不为此增加十来个模块。
- 不要求邮件验证、邮件找回密码或邮件通知；需要时再增加 SMTP 子系统。
- v0.1 不做多实例横向扩展、视频转码和在线图片编辑。

## 8. 技术与运行约束

- Go 1.27，`net/http`、`html/template`、原生 CSS/JS。
- SQLite 使用 `modernc.org/sqlite`，启用 foreign_keys、WAL、busy_timeout。
- Markdown 使用 `goldmark`，输出经 `bluemonday` 清洗。
- 静态资源和模板用 `go:embed` 打入二进制。
- 默认监听 `127.0.0.1:8080`，由 Caddy/Nginx 终止 TLS。
- JSON 结构化日志输出到 stdout；健康检查不记录访问日志。

## 9. 配置环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BOOP_ADDR` | `127.0.0.1:8080` | 监听地址 |
| `BOOP_DATA_DIR` | `./data` | SQLite 与上传目录 |
| `BOOP_BASE_URL` | `http://localhost:8080` | OAuth 回调和绝对链接 |
| `BOOP_SESSION_SECRET` | 无 | 至少 32 字节，生产必填 |
| `BOOP_MASTER_KEY` | 无 | 32 字节 base64，启用密钥保存时必填 |
| `BOOP_SECURE_COOKIES` | `false` | HTTPS 部署必须为 true |
| `BOOP_MAX_UPLOAD_MB` | `10` | 单文件上限 |
| `BOOP_LOG_LEVEL` | `info` | debug/info/warn/error |

对象存储（可选，全部留空则上传保存在 `BOOP_DATA_DIR`）。这些变量现在只用于**播种**：站点第一次启动时把它们的值写进设置表，此后以后台「存储」页为准（见 §6.2）。半配置（设置了任意一个却没有配全）仍然在启动时拒绝并报出缺失的变量名：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BOOP_R2_ENDPOINT` | 无 | S3 API 地址，R2 为 `https://<account-id>.r2.cloudflarestorage.com` |
| `BOOP_R2_BUCKET` | 无 | 存储桶名 |
| `BOOP_R2_ACCESS_KEY_ID` | 无 | R2 API Token 的 Access Key ID |
| `BOOP_R2_SECRET_ACCESS_KEY` | 无 | R2 API Token 的 Secret Access Key |
| `BOOP_R2_PUBLIC_URL` | 无 | 读取对象的主机名：R2 自定义域名或桶的 `r2.dev` 地址 |
| `BOOP_R2_REGION` | `auto` | 签名区域，R2 使用 `auto` |
| `BOOP_R2_PREFIX` | 无 | 桶内的键前缀，例如 `uploads` |

前五个只要设置了任意一个，就全部必填：半配置的对象存储会让进程在启动时报出缺失的变量，而不是在当天第一次上传时才失败。要让这些变量真的能被播种进设置页，还需要 `BOOP_MASTER_KEY`——凭据必须加密入库；没有它时进程照旧按环境变量上传，只是「存储」页无法保存。
