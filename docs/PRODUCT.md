# Boop 产品方案 v0.1

## 1. 产品定位

Boop 是面向个人站长的轻量自托管博客：公开页面保留 X/Twitter 式信息流节奏，发布体验借鉴 Ech0 的快速输入，但不复制社交平台关系链。系统只允许站长发布，读者可注册后评论、回复、点赞和收藏。

## 2. 成功标准

- 1 核 512MB 可稳定运行单实例，推荐 1GB。
- 单个 Go 二进制 + SQLite + 本地上传目录即可部署，无 Node 运行时、Redis、消息队列。
- 首页首屏 SSR；关闭 JavaScript 后仍能阅读文章、摄影和动态。
- 空闲 RSS 目标小于 100MB；缓存命中时首页服务端响应目标 p95 小于 100ms。
- 管理员能在首页直接发布动态、文章或摄影，无需进入复杂后台。

## 3. 角色与权限

| 能力 | 游客 | 注册读者 | 站长 |
|---|---:|---:|---:|
| 阅读、搜索、查看 AI 作者状态 | 是 | 是 | 是 |
| 评论与回复 | 否 | 是 | 是 |
| 点赞 | 否 | 是 | 是 |
| 收藏与查看个人收藏 | 否 | 是 | 是 |
| 发布、编辑、删除内容 | 否 | 否 | 是 |
| 评论审核、系统设置、AI 设置 | 否 | 否 | 是 |

第一位通过初始化命令创建的账户为站长；公开注册永远只能创建 `reader`。

## 4. 内容模型

- `moment`：短动态，正文必填，最多 2,000 字，可附图片或链接。
- `article`：长文章，标题必填，Markdown 正文必填，可配置摘要、封面、标签和 SEO 字段。
- `photo`：摄影内容，正文可选，至少一张图片，可保存地点和拍摄时间。
- 内容状态：`draft`、`published`、`archived`。只有 `published` 出现在公开页面。
- 删除采用软删除；资源文件仅在确认无引用后由维护命令清理。

## 5. 核心体验

### 5.1 首页

- X 风格三栏桌面布局；中栏为信息流，右栏为搜索和 AI 作者状态。
- 左栏是图标条：桌面端也只渲染图标（品牌名与导航文字视觉隐藏，但保留在无障碍树中，读屏仍播报每个入口），并带 `title` 提示。
- 移动端为单栏，AI 作者状态在快捷发布之前，底部导航为首页、文章、摄影、收藏、我的。
- 站长登录时显示快捷发布器；游客和普通读者不渲染发布器 DOM。
- 首页可按全部、文章、摄影筛选；动态只在“全部”出现。

### 5.2 认证

- 邮箱 + 密码注册登录；邮箱无需验证。
- GitHub OAuth 登录；若邮箱与已有账户匹配，只有在 GitHub 返回已验证邮箱时才允许绑定。
- 管理后台可关闭公开注册；关闭后仍可登录和使用 GitHub 绑定的现有账户。
- Session 使用 HttpOnly、SameSite=Lax Cookie；生产环境必须 Secure。

### 5.3 互动

- 评论支持一级回复，最大深度 2。
- 评论审核开关开启时，新评论为 `pending`，否则为 `approved`。
- 点赞和收藏均为登录用户幂等切换；同一用户同一内容最多一条记录。
- 站长可批准、拒绝或删除评论。

### 5.4 AI

- OpenAI-compatible 配置：Base URL、模型、API Key（对话与嵌入模型各一个字段，嵌入用于 v0.2）；密钥使用 `BOOP_MASTER_KEY` 经 AES-GCM 加密后入库。每条密文以它自己的 settings key 作为 additional data 绑定，因此密文只能解回原 setting，换 key 或换行都会认证失败。设置与密钥在每次调用时重新读取并解密，改动无需重启。
- 作者状态：显示在首页右栏搜索框下方；右栏隐藏的窄屏改为显示在快捷发布器之前。内容是不超过 280 字的纯文本加最多 5 个主题词。访问首页时读缓存：仍新鲜直接返回；缓存过期但最新已发布内容的 `updated_at` 不晚于 `source_updated_at`（内容没变，或删除、归档让这个最大值回退；时间戳无法解析时按“可能更新”保守处理）时继续用旧值且不调用模型；缓存过期且存在**严格更新**的内容时先返回旧值，再单飞后台刷新（并发访问不重复生成，失败保留旧值并只记录短码；首次生成失败写入一行只有短码与 5 分钟退避的最小占位行，保持手写兑底文案且退避期内不再打上游）；完全没有缓存时返回手写兑底文案。刷新永不阻塞首页渲染；站长可手动刷新，已有刷新在跑时提示“忙碌”。
- 文章助手：只在站长 + 文章模式的快捷发布器内，以行内控件提供摘要、标签与 SEO 建议（该控件只在 `ai.api_key` 能真正解密且非空时渲染，缺少 `BOOP_MASTER_KEY` 或密文损坏时隐藏，不提供必然失败的按钮）；建议不会自动覆盖草稿，摘要与标签必须点“采用”才写入，SEO 只提供复制。输入与输出都有明确上限（摘要 300 字、标签 8 个且每个 30 字、SEO 标题 160 字与描述 300 字）。
- 语义搜索与站内问答属于 v0.2：先以 SQLite FTS5/关键词检索作为可用基线；只有配置了 embedding 模型时启用向量增强。
- 所有 AI 调用都有超时（20 秒）、并发上限（全进程 2 个）、请求与响应体上限和失败降级；密钥、提示词、模型输出与上游响应体不进入错误信息、日志或缓存。

### 5.5 搜索与 RSS

- 搜索是公开的关键词检索，只用 SQLite FTS5（`posts` 的现有全文索引），不引入 embedding、向量表、语义搜索或外部检索服务。
- 查询词按 Unicode 字母/数字切分，每个词单独加引号后用 `AND` 连接：引号、`*`、`(`、`)`、`-`、`^` 等 FTS5 语法字符只会被当成分隔符丢弃，输入无法改变查询结构；超过 100 字的查询返回 400。
- 空白查询与只有标点的查询都渲染成零结果状态（不是错误），也不会暴露 SQLite 语法错误；结果按 `published_at DESC, id DESC` 稳定分页（默认 20、最大 50），只包含已发布且未删除的内容。
- `/search` 是 X 风格的结果流：中栏顶部是紧凑搜索行加结果计数，下面是按分隔线分割的连续结果行（类型标签、标题或正文首行、高亮片段、相对时间、指向 `/p/{slug}` 的链接）；移动端搜索行仍在顶栏下方、结果流仍为单列，底部导航不变；左栏“搜索”项在 `/search` 高亮。
- 片段取自索引里匹配最佳的那一列（标题、正文或摘要），并且只以**纯文本片段**交给模板：高亮由模板静态输出的 `<mark>` 完成，每段文本仍由 `html/template` 自动转义，所以存储正文里的 HTML（哪怕带 U+0002 / U+0003）永远不会执行，也不会破坏标签结构。
- 结果计数只说当前页：“本页 N 条”来自本次返回的行数，服务端不做 COUNT，也不把单页数量冒充总数。
- RSS 2.0 输出在 `/feed.xml`：最新 50 条已发布内容，用一条只读 `slug`/`type`/`title`/`body_markdown`/`excerpt`/`published_at` 的窄查询，不读 `body_html`、图片与标签；绝对链接只来自 `BOOP_BASE_URL`（不读请求 Host 或转发头）；描述是**真正的纯文本**（文章正文经 Markdown 渲染后只取可见文本，原始 HTML 不会出现）并由编码器自动 XML 转义；页面 `<head>` 带 `rel="alternate"` 发现链接。
- 语义搜索与站内问答仍是 v0.2，只有在配置了 embedding 模型并测量后才引入向量表；当前检索返回的 `search.Result` 就是将来复用的形状。

## 6. 管理设置

- 注册开关。
- 评论总开关与评论审核开关。
- 站点名称、简介、头像、时区、每页条数。名称与头像会真实用于页面品牌（标题后缀、导航品牌、搜索占位、首页文案）与内容头像，头像留空时依次回退到站长账号头像、内置图标。
- GitHub OAuth Client ID/Secret。
- AI Base URL、模型、加密 API Key、状态缓存天数。
- 上传目录、单文件大小和允许的 MIME 类型由环境变量控制，不在网页端任意改路径。

## 7. 非目标

- 不做关注、转发、私信、用户发帖、多人协作发布。
- 不引入 Redis、Elasticsearch、独立前端 SPA、任务队列或微服务。
- 不要求邮件验证、邮件找回密码或邮件通知；需要时再增加 SMTP 子系统。
- v0.1 不做 S3、多实例横向扩展、视频转码和在线图片编辑。

## 8. 技术与运行约束

- Go 1.27，`net/http`、`html/template`、原生 CSS/JS。
- SQLite 使用 `modernc.org/sqlite`，启用 foreign_keys、WAL、busy_timeout。
- Markdown 使用 `goldmark`，输出经 `bluemonday` 清洗。
- 静态资源和模板用 `go:embed` 打入二进制。
- 默认监听 `127.0.0.1:8080`，由 Caddy/Nginx 终止 TLS。
- JSON 结构化日志输出到 stdout；健康检查不记录访问日志。

## 9. 配置环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `BOOP_ADDR` | `127.0.0.1:8080` | 监听地址 |
| `BOOP_DATA_DIR` | `./data` | SQLite 与上传目录 |
| `BOOP_BASE_URL` | `http://localhost:8080` | OAuth 回调和绝对链接 |
| `BOOP_SESSION_SECRET` | 无 | 至少 32 字节，生产必填 |
| `BOOP_MASTER_KEY` | 无 | 32 字节 base64，启用密钥保存时必填 |
| `BOOP_SECURE_COOKIES` | `false` | HTTPS 部署必须为 true |
| `BOOP_MAX_UPLOAD_MB` | `10` | 单文件上限 |
| `BOOP_LOG_LEVEL` | `info` | debug/info/warn/error |
